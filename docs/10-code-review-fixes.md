# 代码审阅后的修改

用户在 2026-11-02 授权修改审阅发现的问题，并授权按需使用真实模型 API。用户随后提供目标仓库 `git@github.com:Lancycool/planning-Agent.git`。本轮保留原有费用、时间和串行业务规则。

| 问题 | 修改 | 验证 |
| --- | --- | --- |
| 重复生成被拒绝后，程序把成功步骤改成 rejected。 | 执行程序分别维护调用记录和计划状态。后续失败或拒绝不会覆盖仍有效的成功结果。完成检查也核对保存脚本、费用和计划状态。 | `test_rejected_retry_preserves_successful_plan_step` 验证重复调用被拒绝，但最终计划仍成功，费用只发生一次。 |
| 网页为每次提交生成新 ID，重复提交会再次执行。 | 网页在 sessionStorage 保留请求 ID。服务端验证并使用客户端 ID。用户改变输入、改变模式或新建任务时才获得新 ID。 | HTTP 测试验证重复提交不再调用模型，冲突输入返回冲突，新任务可以执行。前端测试验证重试、刷新、改输入和新任务行为。 |
| 复用导出目录时，旧 saved-plan 仍然存在。 | 导出程序移除不属于本次结果的方案或场景文件。CLI 在请求冲突时不再附上旧请求的已保存方案。 | 导出测试覆盖成功后导出待补充状态，以及相同 ID 不同输入的冲突导出。 |
| catalog 缺字段或字段类型错误会在执行中崩溃。 | 完整 Pydantic 模型校验素材、方案、工具规则和计费口径。程序在建立数据库和调用模型前拒绝无效配置。 | 8 组测试覆盖缺交付字段、重复素材 ID、错误标签类型、负耗时、布尔费用、不支持的计费、非零保存费和缺默认方案。 |

本轮还增加独立的结果检查程序。检查程序按实际 catalog 重算费用、耗时、估算缺口与可行性，并核对保存产物、费用事件、步骤状态和执行上限。测试会主动破坏费用、时间、估算和保存信息，确认检查程序能够发现不一致。

真实模型扩展场景覆盖价格变化、时间重规划、连续生成失败、持续保存失败和无素材。程序对每个扩展场景独立运行两次，并保留所有结果。评估文档记录实际表现，不把重试后的记录替换成先前失败记录。
