# Agent 方案设计

## 1. 方案状态

用户已确认 Python、CLI、LangGraph、本地 SQLite、单任务串行运行、百炼的 `deepseek-v4.1-flash-1017` 和北京地域 Host。用户也已确认本轮预算、模拟耗时、重复请求、费用发生时点、输入冲突和可选续跑规则。开发者按 `06-decisions.md` 的确认边界开展后续工作。

LangGraph 的节点、状态和模型接入建议见 `07-langgraph-model-design.md`。本文件其余“建议”内容仍属于设计细节，不能据此扩大已确认范围。

## 2. 职责划分

| 部分 | 主要职责 |
| --- | --- |
| 模型 | 模型提出计划、选择工具、读取结果、调整方案、请求补充或停止。 |
| LangGraph | 框架通过状态、节点和条件边组织执行循环。框架不替模型决定业务方案。 |
| 执行程序 | 程序校验动作和参数、执行工具、管理状态、记录费用与 Trace、检查上限。 |
| 业务工具 | 工具根据本地素材和费用、耗时表返回可核对的结果。 |
| 状态存储 | 存储保存任务、步骤、计划版本、工具结果和保存凭据。 |
| 验证程序 | 测试检查状态、约束、结果保留和实际保存行为。 |

程序可以阻止违规保存，但程序不能预先替模型选好替代方案。真实模型记录不能使用提前写好的决策来冒充。

## 3. 建议执行循环

1. 程序校验输入，并检查请求是否已经存在。
2. 程序向模型提供目标、约束、工具说明、已有状态和剩余调用次数。
3. 模型返回一个结构化动作。动作可以调用工具、更新计划、请求补充或结束。
4. 程序校验工具白名单、参数、依赖和次数限制。
5. 程序执行动作，并把结构化结果写入状态。
6. 模型观察最新结果，再选择下一步动作。
7. 程序核验终态。模型声明完成，但保存凭据缺失或约束未通过时，程序拒绝完成声明。

程序建议同时限制模型轮数与工具调用次数。非法动作也消耗轮数，避免系统因反复返回错误动作而无限运行。具体数值在实现前确定。

## 4. 工具契约草案

| 工具 | 输入重点 | 输出重点 |
| --- | --- | --- |
| search_materials | 工具接收主题或查询条件。 | 工具返回素材 ID、事实、可用选项和相关费用、耗时信息。 |
| generate_script | 工具接收素材 ID、内容要求和方案版本。 | 工具返回脚本、来源、费用与耗时记录。 |
| estimate_plan | 工具接收当前方案、费用规则和时间状态。 | 工具返回费用明细、总额、剩余时间、约束结果与缺口。 |
| save_plan | 工具接收当前已校验方案与防重复标识。 | 工具返回保存状态、方案 ID、版本和可读取位置。 |

工具统一返回状态、结果、错误码和是否可重试。工具只有部分结果时，必须逐项标明成功与失败。具体字段在用户确认后确定。

脚本生成工具可以使用可复现的本地生成逻辑，因为考核允许 Mock 业务工具。项目必须标明这项限制。外层动作选择仍然需要真实模型证据。

## 5. 状态与结果保留

任务建议使用 `pending`、`running`、`waiting_input`、`completed`、`incomplete` 状态。原因码单独说明预算不足、时间不足、工具失败、上限触发等原因。

步骤建议使用 `pending`、`running`、`succeeded`、`failed`、`skipped` 状态。程序必须使用实际工具结果更新步骤。

每个步骤保存输入、依赖版本、工具结果和调用记录。成功结果可以保留，但只有输入和依赖仍然适用时才能复用。方案调整使结果失效时，系统保留旧结果供核对，并标明它不再属于当前方案。

程序不能在每次重规划时清空已有结果，也不能把不适用的旧估算套用到新方案上。

## 6. 预算与截止时间

建议将预算解释为模拟业务费用上限。系统分别记录已发生费用、后续预计费用和当前方案费用。模型 API 用量单独记录；费用不可获得时，系统标记未知，不填写为零。

费用规则表需要明确每个工具调用是否收费及费用发生时点。已确认规则规定估算不产生支出，失败调用不收费。程序必须在收费步骤前检查费用。系统从费用事件和方案明细计算总额，避免重复相加。

建议使用整数最小单位保存费用。系统允许费用恰好等于预算。

系统从固定测试起点累加各次工具的模拟耗时，失败耗时也计入。系统同时记录实际运行用时，两者不能混用。重规划不能重置起点。系统允许预计完成时间恰好等于截止时间。

参考场景中，方案 A 估算为 12，替代方案 B 估算为 8。只有当已发生费用加上 B 的后续费用仍不超过预算 10 时，系统才能接受 B。测试数据需要明确这些数字的组成。

保存程序必须核验当前方案的最新估算和实际状态。保存本身若产生费用或耗时，估算也必须包含这部分。

## 7. 重复执行与保存

系统使用请求 ID 加输入指纹识别任务。相同 ID、相同输入返回已有结果；相同 ID、不同输入返回冲突。用户修改任务时使用新请求 ID。

首版建议对已经结束但未完成的任务也返回原结果。再次尝试和失败续跑需要另行定义，不能暗中复用重复请求入口。

建议使用本地 SQLite 保存状态和唯一约束，并将评审材料导出为 JSON。保存成功凭据必须对应实际产物。保存失败不能报告完成。首版只保证串行使用，并明确并发边界。

## 8. 工具失败与模型失败

程序把工具错误反馈给模型。模型决定改选方案、有限重试或停止。程序只负责执行上限和合法性检查。

模型超时、认证失败或不可用时，程序返回明确未完成状态。在线运行不能自动切换为 Mock 后继续声称真实模型完成。

离线模式应明确标记 `model_mode=mock`。离线模式可以用固定响应验证执行程序，但这类记录不用于证明真实模型决策。

## 9. Trace 与输入边界

Trace 保存运行 ID、模型模式、轮次、计划版本、动作、工具参数、返回摘要、后续动作、简要依据、费用事件、时间和终态。Trace 不要求模型内部思维过程。

程序把检索素材视为业务数据，不能把素材中的指令当作工具授权。程序不执行模型生成的任意命令，也不接受任意保存路径。程序不把密钥写入 Trace。

## 10. 暂定模块

实现建议分成输入输出、模型适配、循环执行、状态与存储、四类业务工具、Trace 和测试。开发者应按职责拆分代码，避免为展示目录而增加无实际用途的层次。

## 11. 当前实现

项目已实现 `schemas.py`、`storage.py`、`tools.py`、`models.py`、`engine.py` 和 `cli.py`。LangGraph 1.2.18 负责 StateGraph、节点、条件边及图上限。OpenAI SDK 2.54.0 只承担百炼兼容协议调用，不参与业务决策。

图使用一个完整任务快照作为状态字段。节点先复制快照，再统一写入 SQLite，避免列表合并时重复追加费用。成功保存时，业务方案和任务快照在同一事务内提交。

模型每轮收到当前约束、计划、已检索素材、成功脚本、最近观察和近期动作。模型看不到尚未发生的故障配置。系统仅保存函数参数、工具结果和简要动作依据，不保存供应商返回的内部推理内容。

当前合成表只在脚本生成成功时收费：完整方案为 12，精简方案为 8。其他工具免费。这个选择减少首版计费歧义，并保留重规划后累计已发生支出的检查。当前加载器拒绝在其他工具上配置费用，避免数据表与实现不一致。

默认上限为 16 次模型请求、12 次业务工具尝试和 100 个图执行步。脚本生成后，程序使旧估算失效。保存后，程序只接受结束动作。任务计划中的步骤状态与实际工具记录分别输出。

## 12. 审阅后的状态与输入检查

执行程序把单次调用记录与计划步骤状态分开维护。拒绝或失败的重复调用保留在 steps 和 Trace 中，但不会清除仍然有效的成功结果。完成检查核对实际保存计划、脚本、费用和计划步骤状态。

项目用完整 catalog 数据模型检查素材 ID、素材字段、方案费用和耗时、工具参数与支持的计费口径。加载器在模型调用前拒绝不完整或不支持的配置。默认离线模拟器依赖 premium 和 basic 两个方案名，加载器会检查这两个方案存在。

网页使用客户端任务 ID，并在同一标签页的 sessionStorage 中保留 ID。相同输入重试和刷新复用 ID。新任务或输入变化产生新 ID。服务端沿用核心程序的重复请求和冲突检查。

导出程序按本次结果更新文件。没有保存产物时，程序移除旧 saved-plan。请求冲突时，CLI 不会导出同 ID 的旧方案。
