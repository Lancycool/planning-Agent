# LangGraph 与百炼接入设计

## 1. 当前状态

用户已确认 Python、CLI、LangGraph、本地 SQLite、串行运行和阿里云百炼的 `deepseek-v4.1-flash-1017`。用户也已提供北京地域 Host。本文件细化设计，不代表代码已实现。其他确认边界见 `06-decisions.md`。

## 2. 框架职责与节点建议

LangGraph 的 Graph API 使用状态、节点和边组织循环。项目建议使用 StateGraph 管理业务状态。公开框架能力依据见文末官方资料。

| 节点 | 节点职责 | 后续方向 |
| --- | --- | --- |
| intake | 节点校验输入，并查询重复请求。 | 新请求进入 decide；缺字段或重复请求进入 finalize。 |
| decide | 节点调用真实模型，提供约束、工具说明和观察结果。 | 模型响应进入 validate_action。 |
| validate_action | 节点检查工具、参数、依赖和执行额度。 | 合法调用进入 execute；可纠正错误回到 decide；结束请求进入 finalize。 |
| execute | 节点执行一个业务工具，记录成功、失败或部分成功结果。 | 工具结果回到 decide；额度用尽时进入 finalize。 |
| finalize | 节点核验完成条件，保存真实终态并形成输出。 | 图进入 END。 |

输入校验、重复请求处理和上限控制可以使用固定规则。模型负责选择素材、调整计划、寻找替代方案和决定停止。条件边不能根据费用超限直接替模型选中替代方案。

节点划分属于设计建议。开发者需要结合已确认范围确定最终结构。

## 3. 状态建议

图状态包含请求与约束、对话消息、计划版本、步骤结果、费用事件、模拟耗时、当前动作、最近观察、调用计数和任务终态。

消息与费用事件需要采用明确的追加或合并规则。步骤结果需要按稳定标识更新。节点不能用局部状态覆盖全部历史结果，也不能因重复合并而重复计费。

图状态用于本次执行决策。业务存储用于重复请求检查和结果查询。框架 checkpoint 负责执行恢复，不能直接替代业务唯一约束。首版把失败续跑作为可选项，因此不建议先增加完整恢复系统。

## 4. 百炼接入建议

百炼官方文档列出该模型支持 Chat Completions 和 Function Calling。项目建议采用兼容聊天接口与函数调用，并由程序校验参数。官方结构化输出说明列出 JSON Object，未提供 JSON Schema 支持，因此项目不依赖服务端严格 JSON Schema 校验。

模型适配层负责消息、工具定义、响应和用量的转换。业务节点不直接处理供应商字段。兼容协议不意味着项目可以自行更换服务商或模型。

用户已提供北京地域业务空间 Host。项目采用以下配置，并已通过三组真实模型案例验证。

| 配置 | 当前值 |
| --- | --- |
| 服务商 | 阿里云百炼。 |
| 模型 ID | `deepseek-v4.1-flash-1017` |
| Base URL | `https://ws-63tuqwgnvti8179g.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` |
| 协议建议 | 项目使用 Chat Completions 和函数调用。 |
| 密钥 | 用户在本地环境配置，文档不保存实际值。 |
| 账号权限、额度和计费类型 | 本次模型调用已成功；剩余额度和实际账单金额尚未查询。 |

程序从本地配置读取地址和模型名称。开发者不能根据公开文档推定账号权限或可用额度。

首版建议每轮只执行一个业务工具。如果模型一次提出多个调用，程序需要先检查依赖并反馈处理规则，不能直接并行执行互相依赖的步骤。

项目不默认启用供应商内置搜索或代码执行，因为本题要求的是本地四类业务工具。

## 5. 执行上限与失败收尾

图执行步数、模型请求次数和业务工具次数属于不同计数。项目需要分别记录。

程序先通过业务额度主动结束，再用 LangGraph 的 recursion_limit 防止图失控。开发者还需要处理 GraphRecursionError，并从最近保存状态形成未完成输出。程序不能只返回异常堆栈而丢失成功结果。

参数错误、工具失败和非法动作需要成为模型可观察的结果。模型不可用时，系统明确返回未完成。在线模式不能暗中切换为 Mock。

## 6. 兼容性验证步骤

1. 开发者确认接口类型、地域、Base URL 和本地密钥配置方式。
2. 开发者检查基本对话，并记录实际模型标识和用量。
3. 开发者检查工具调用参数能否通过本地校验。
4. 开发者检查工具结果回传后，模型能否选择后续动作或结束。
5. 开发者运行正常、超预算和工具失败路径，并保存实际记录。

上述基本对话、函数调用和后续动作已经通过实际在线运行验证。实际记录见 `examples/online/`。框架与模型依赖版本已通过 `uv.lock` 锁定。真实运行结果和局限以 `03-evaluation.md` 为准。
