## 首版问题与处理

初次测试有 25 项在建立临时目录时出错，另有 5 项通过。原因是当前 Windows 受管环境不允许访问 pytest 创建的受限目录。项目改用工作区内隔离目录，并关闭 pytest 缓存，后续 33 项测试通过。测试运行目录位于被忽略的 .runtime 内。

初版模型状态中包含故障注入配置，模型可能提前看到计划中的失败。项目已把业务调用额度与故障配置拆开，并用模型适配测试检查未知故障不会出现在请求中。

首批真实模型会直接选用可负担方案。最终重规划案例增加先评估完整方案的业务偏好，模型才实际观察到 12 超预算 10，并改选 8。工具失败案例中，模型实际改用精简方案，成功素材得到保留。

模型的简要理由仍有单位和时间描述不准确的情况。项目没有隐藏这些记录。程序使用计算结果核验预算、时间与终态，评估文件也说明了自由文本理由的限制。

## 2026-11-02 的改进

本轮发现，成功产物与最近一次调用状态不能直接共用一个字段。程序拒绝重复调用时，成功产物仍然有效。计划需要保留成功状态，调用记录需要如实保留拒绝结果。

网页和 CLI 需要使用同一套重复执行规则。页面禁止连点只能减少误操作，稳定请求 ID 才能让重试真正返回原结果。导出目录也需要明确处理旧文件，否则有效的 JSON 仍可能组成一组错误材料。

本轮还把结果检查扩展到实际费用表。检查程序重新计算每次调用费用、模拟耗时和缺口。真实模型验证增加重复运行，并保留失败与不同的合法动作。具体结果见评估文档。

项目仍未实现失败续跑、并发和真实业务工具。本轮没有完整记录从修复开始到交付结束的总工时。运行清单和输出保留了验证时间与实际运行秒数，开发者不能据此声称完整项目在三小时内完成。
